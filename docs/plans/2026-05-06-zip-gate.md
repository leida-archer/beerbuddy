# ZIP Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use parallel-execution (recommended) or execute-plan to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace today's marketing homepage with a minimal ZIP-entry form, validate ZIPs server-side at `/deals` against a 4-ZIP Nevada County allowlist, redirect invalid/missing ZIPs back home with error context, and swap the `/deals` header right-side text from chain list + deal count to a single underlined `Location: <zip>` link.

**Architecture:** URL-driven, server-rendered, no client JS. A new pure module `src/lib/geo/zip.ts` holds the allowlist + `isValidZip` predicate. The `/deals` page validates `searchParams.zip` at the top of `DealsPage` and uses Next 15's `redirect()` for both branches (missing → `/`, invalid → `/?error=region&zip=…`). The homepage is a plain HTML `<form action="/deals" method="get">` — submit produces `/deals?zip=…` and the browser navigates. Error UI renders inline below the form when `?error=region` is present.

**Tech Stack:** Next.js 15 App Router server components · Tailwind CSS · Vitest · Bun · existing Golden Hour design tokens (`bg-ink`, `text-bg`, `border-rule`, `border-error`, `bg-surface`, `font-mono`, `text-warm`, `text-error`, `decoration-rule`, etc.)

## Task ordering rationale

Tasks 1 → 5 are ordered so each commit leaves the repo in a working, tested state:

1. **Task 1** (zip.ts module) is fully independent — nothing else imports it yet.
2. **Task 2** (url.ts extension) lands the `PageState.zip` field with default `""` and updates the test fixture. Existing `/deals` URLs get `?zip=` appended (empty value) for one commit window — functional but visually awkward. Acceptable: no end-user reaches this state because Task 3 lands immediately after.
3. **Task 3** (gate) ensures `/deals` is unreachable without a valid zip. After this, the empty-zip URL form vanishes from production.
4. **Task 4** (homepage) provides the only legitimate entry path now that Task 3 redirects bare `/deals` to `/`.
5. **Task 5** (header swap) is a pure visual change with no behavioral coupling to Tasks 1–4 — could in principle be reordered, but kept last so it lands after the data dependency on `state.zip` is fully established.

Each task ends with its own atomic commit. Reverting any single task is one `git reset` away.

```typescript
// src/app/deals/url.ts

export type SortKey = "best" | "cheap" | "oz";

export interface PageState {
  zip: string;
  sort: SortKey;
  pack: string | null;
  style: string | null;
  pickerOpen: boolean;
}

export const DEFAULT_SORT: SortKey = "best";

/**
 * Parse Next.js searchParams into a typed PageState. `zip` defaults to
 * "" when absent; the production redirect at /deals catches the
 * empty-zip case before this helper's output is rendered.
 */
export function parsePageState(
  sp: Record<string, string | string[] | undefined>,
): PageState {
  const sort = asString(sp.sort);
  return {
    zip: asString(sp.zip) ?? "",
    sort: sort === "cheap" || sort === "oz" ? sort : DEFAULT_SORT,
    pack: asString(sp.pack),
    style: asString(sp.style),
    pickerOpen: asString(sp.fp) === "open",
  };
}

/**
 * Build a /deals href that applies the given changes on top of the
 * current state. Pass `null` to clear pack or style. `zip` is always
 * emitted — there is no default to omit. Default sort and closed
 * picker are omitted from the URL.
 */
export function buildHref(state: PageState, changes: Partial<PageState>): string {
  const next: PageState = { ...state, ...changes };
  const sp = new URLSearchParams();
  sp.set("zip", next.zip);
  if (next.sort !== DEFAULT_SORT) sp.set("sort", next.sort);
  if (next.pack) sp.set("pack", next.pack);
  if (next.style) sp.set("style", next.style);
  if (next.pickerOpen) sp.set("fp", "open");
  return `/deals?${sp.toString()}`;
}

export function asString(v: string | string[] | undefined): string | null {
  if (typeof v === "string" && v.length > 0) return v;
  if (Array.isArray(v) && v[0]) return v[0];
  return null;
}
```

Three structural changes from the existing file:
- `PageState` gains a `zip: string` field (placed first by convention).
- `parsePageState` reads `sp.zip` with `?? ""` default.
- `buildHref` emits `zip` unconditionally as the first param. The previous `q ? "/deals?…" : "/deals"` short-circuit is replaced by an unconditional `/deals?${sp.toString()}` because every URL now has at least `zip=…`.
- `asString` is now `export function asString(...)` instead of private — Task 4's homepage imports it.

## Notes for the implementer

- **Don't add `'use client'`** — the homepage form is a plain HTML `<form>`, not a client component. The `/deals` page stays server-rendered. Adding a client boundary defeats the architecture.
- **Don't introduce server actions** — the form GETs `/deals` directly. Validation lives in `/deals` (one site).
- **Don't extend `parsePageState` to validate the ZIP** — validation is the gate's job in `/deals/page.tsx`. The helper is intentionally permissive ("treats `zip` as a plain string") so it has a defined contract independent of the gate.
- **Don't list the supported ZIPs in `ZipErrorBlock`** — explicit user call. The error stays terse.
- **If the dev server hits webpack errors after Task 2 or 3**, kill it, `rm -rf .next`, restart with `bun run dev`. Next.js's incremental cache occasionally drifts after structural type changes; a clean rebuild fixes it.
- **The `Location:` link goes to `/`, not back to the previous filter URL** — this is the explicit design choice. Changing ZIP invalidates the deal context, so dropping filters is correct.
