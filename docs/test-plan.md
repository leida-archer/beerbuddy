## Affected Pages/Routes

- `/` (entry page) — ZIP input, "use my location" button, empty/loading/error states
- `/deals?zip=NNNNN` (deal list) — filter chips (pack size, style, $/oz), ranked deal cards, distance "X mi" display, "limited history" caveat for cold-start, pagination if >25 results
- `/deals/[productSlug]` (deal detail) — big price, $/oz, 90-day price-trend SVG graph, list of stores carrying product, "Get directions" deeplink to Apple/Google Maps
- `/admin/indie` (manual entry, password-gated) — store selector, product autocomplete, price entry form, recent-entries list
- `/admin/aliases` (alias confirmation, password-gated) — candidate-match list, one-click confirm/reject, undo
- `/api/deals` (read API) — query params: zip, sort, filter; reads from `product_deal_scores` matview
- `/api/admin/*` (admin API) — password + rate-limit middleware, returns 401/429 appropriately

## Key Interactions to Verify

- **Cold open → see deals** (golden path): Land on `/`, enter `95945`, tap submit → `/deals?zip=95945` shows ≥1 ranked card within 2 seconds.
- **Use-my-location** flow: Tap button → browser permission prompt → on grant, lat/lon → reverse-lookup nearest ZIP → push to `/deals` URL.
- **Filter chips**: Toggle "12-pack" chip → list updates to only 12-packs. Toggle "$/oz" sort chip → list re-sorts.
- **Distance display**: Each card shows distance from user's ZIP centroid in miles, one decimal.
- **Detail page**: Tap any card → product detail loads with price-trend SVG + list of stores carrying this product (cheapest first).
- **Directions deeplink**: Tap "Directions →" on detail → opens Apple Maps on iOS / Google Maps on Android via universal URL.
- **Admin password gate**: Hit `/admin/indie` → password prompt → wrong password 5x → 429 "too many attempts" for 1 hour.
- **Admin manual entry**: Correct password → form → submit → row appears in `price_events` with `source = 'manual_indie'`.
- **Alias confirmation**: `/admin/aliases` → confirm a candidate match → `product_aliases` row written → matview refresh queues for next cron tick.

## Edge Cases

- **ZIP not in Nevada County data** (e.g., user enters `94103` San Francisco) — show "BeerBuddy currently only covers Nevada County, CA" with link back to `/`.
- **Empty deals list** for valid Nevada County ZIP (cold-start, no data yet) — show "Building our price database — check back next week" with stores-covered list.
- **Limited-history caveat**: A product with <30 days of price history shows "limited history" badge on its card and detail page; deal score is computed against the available window with the caveat visible.
- **Adapter HTTP timeout** during ingestion run — orchestrator records the failure to `runs` table, continues with remaining adapters, sends a per-run summary with failures listed.
- **Adapter parse failure** — bad HTML → all parse-failed products go to `quarantine_events` with raw row + reason; run continues.
- **Sanity bounds reject** (Issue 3A) — price > 5x or < 0.2x prior → rejected to `quarantine_events`, not written to `price_events`. UI never sees the bad row.
- **LLM Zod parse failure** (Issue 7A) — bad LLM output → row to `llm_parse_failures` with raw response + Zod error; SKIP write.
- **Matview refresh while a query is mid-flight** — Postgres `REFRESH MATERIALIZED VIEW CONCURRENTLY` ensures readers don't block.
- **Distance to a Truckee-only chain store** when user is in Grass Valley (~80 mi) — store listed but de-prioritized below 25mi threshold.
- **Product alias missing** — same product appears under two SKUs in different chains. Detail page shows two separate products until alias is confirmed.
- **Indie store entry stale** (>30 days since last manual update) — UI shows "last updated MMM DD" on indie store cards. Stale entries de-emphasized.
- **GPS denied** — fall back to ZIP input flow, no error toast (graceful).
- **Geolocation says "Auburn"** but user is actually 5 miles into Nevada County — distances will be off by ~5 miles; acceptable per the centroid approximation in the design doc.

## Critical Paths

End-to-end flows that must work for the success criteria to hold:

1. **Personal-use weekly path**: Adapter cron runs Wednesday → matview refreshes → developer opens `/` Friday afternoon → enters home ZIP → sees current week's best deal at correct store → taps directions → drives there → price on shelf matches what BeerBuddy showed (within ±$0.50 acceptable for chain pricing variation).

2. **Friend soft-launch path** (week 8): Friend in 95946 opens shared URL → sees a relevant deal → understands "limited history" caveat without explanation → trusts the result.

3. **Failure-tolerant ingestion path**: Daily cron runs → 1 of 7 adapters fails → matview still refreshes from the 6 successful chains → app still shows deals → developer sees per-run failure email → fixes adapter the next weekend without the app appearing "broken" to users in the meantime.

4. **Bad-data resilience path** (Issue 3A): Adapter ingests glitchy $99 price for Sierra Nevada → sanity bounds reject → row goes to `quarantine_events` → app continues showing $13.99 from prior day → developer sees quarantine entry on weekly review.

5. **Product normalization path** (Week 5): Adapter writes `RALEYS_SKU_12345` for "Sierra Nevada Pale Ale 12pk" while Save Mart writes `SAVEMART_SKU_67890` for the same product → admin candidate-match UI surfaces the pair → one-click confirm → `product_aliases` row → next matview refresh shows them as ONE product with two stores.

6. **Admin abuse-prevention path**: Bot hits `/admin/indie` with random passwords → 5 fails → IP rate-limited 1 hour → on retry, sees 429.
