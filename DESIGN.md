# Design System — BeerBuddy

> Generated by `/design-consultation` on 2026-05-04. The directional name for this system is **Golden Hour**. It is the source of truth for all visual decisions in the BeerBuddy codebase. Update via the same skill, or by direct edit accompanied by an entry in the Decisions Log.

## Product Context

- **What this is:** BeerBuddy is a mobile-primary responsive web app (PWA) that surfaces the best beer deals at chain and indie stores in Nevada County, CA. The differentiator is "deal vs. 90-day baseline" framing rather than just sticker-cheapest.
- **Who it's for:** Nevada County residents (~100K) shopping for beer at Raley's, Save Mart, Grocery Outlet, Holiday Market, SPD, Walmart Grass Valley, BevMo Auburn, and a handful of indie liquor stores.
- **Space/industry:** Local consumer utility — adjacent to (but distinct from) brewery brand sites, generic price-comparison apps (Drizly, BoozApp), and civic-data tools.
- **Project type:** Mobile-primary PWA with admin pages for indie price entry and product alias management.

## Aesthetic Direction

- **Direction:** Golden Hour — mature, sophisticated, lively-but-restrained. The mood is the moment when a brewery's lights warm up at 5pm: glasses clinking, dice rolling, wood glowing, the night about to begin.
- **Decoration level:** Minimal — typography and hairline rules do all the structural work. No drop shadows, no gradient buttons, no decorative ornaments (no `※` or filigree — earlier iteration removed them). Personality comes from color and type, not chrome.
- **Mood:** A friend opens the app and feels mature taproom-at-golden-hour: capable adult product, considered, warm without being twee. The user closes the app feeling on-the-verge of an amazing night.
- **Reference influences:** modern brewery menus, third-wave coffee roaster identities (e.g., Ritual, Sightglass), Aesop product cards. Explicitly NOT: Drizly/BoozApp generic SaaS, Tailwind Inter+indigo defaults, brewery-brand grunge type, kitschy beer iconography.

## Typography

All three faces are free under permissive licenses (OFL or Apache); load via Google Fonts and Fontshare.

```html
<link href="https://api.fontshare.com/v2/css?f[]=editorial-new@200,400,500,500i,700&f[]=general-sans@300,400,500,600,700&display=swap" rel="stylesheet">
<link href="https://fonts.googleapis.com/css2?family=Bricolage+Grotesque:opsz,wght@12..96,200..800&family=Geist+Mono:wght@200..800&display=swap" rel="stylesheet">
```

| Role | Family | Why |
|------|--------|-----|
| **Display / Hero** | Editorial New (Fontshare) | High-contrast modern serif. Mature gravity without going wedding-y. Provides the "editorial" character that the rest of the system rests on. |
| **Body / UI** | Bricolage Grotesque (Google Fonts) | Distinctive variable sans with optical-size axis. Pairs warmly with Editorial New. Avoids the Inter/Roboto default trap. |
| **Data / Prices** | Geist Mono (Google Fonts) | Tabular numerals via `font-feature-settings: "tnum" 1`. Clean, calibrated, less typewriter-y than JetBrains Mono. Used for prices, savings amounts, freshness timestamps, status-bar content. |
| **Code (if shown)** | Geist Mono | Same family as data. |

**Italic discipline.** Editorial New italic exists in the system but is reserved for very rare emphasis — the v0.4 system explicitly stripped italic flourishes from prices/savings/section titles for a more mature, restrained tone. Default to upright. Use italic only when a genuine semantic emphasis exists (rare).

### Type scale

```
  xs   12 / 16    — caption, footnote
  sm   13 / 18    — chip, button, small UI text
  base 14 / 20    — body small / muted
  md   16 / 24    — body default
  lg   18 / 28    — body large, important paragraph
  xl   22 / 28    — display small
  2xl  32 / 36    — section subhead, detail page title
  3xl  40 / 44    — section title (in marketing surfaces)
  4xl  56 / 56    — display large (rare)
  hero clamp(48px, 9vw, 92px) / 1.0  — hero only
```

Body line-height tightens at smaller sizes (~1.5) and opens at larger sizes (~1.55–1.6) for readability.

### Numerals

Always use `font-feature-settings: "tnum" 1` on price-bearing elements. Without it, "$13.99" and "$15.49" misalign in vertical lists.

## Color

Two-tone foundation: a warm wheat-oak page color and a pure-white content surface. Two accents (warm + cool) and two semantic colors (success + error). One ornament gold reserved for very rare flourishes (currently unused in v0.4 — kept in palette for future).

### Light mode

```
  bg          #F4E8CB   wheat-oak — page · between cards · header band
  bg-soft     #ECDDB8   deeper warm tint — chip hover · banner alt
  surface     #FFFFFF   content surface — cards · inputs · phone interior
  ink         #1F1610   espresso near-black — body text · borders
  muted       #7A6855   warm tobacco-gray — secondary text · timestamps
  rule        #D9C9A4   warm hairline — dividers · card borders (light)
  rule-soft   #E5D6B2   even lighter rule — internal dashed dividers

  warm        #B8651E   old-fashioned amber — BEST DEAL eyebrow · brand accent · price-trend "now" marker
  cool        #2D4A3E   deep forest — links · chip-active fill · trend line · active filter
  gold        #C8941F   reserve gold — currently unused (saved for future flourish)

  success     #5C7A2E   olive — savings amounts ("22% off")
  error       #963A2D   brick — errors · quarantine highlights

  warm-soft   #F0D7B0   peach — used sparingly for warm tint backgrounds
  cool-soft   #C8D4CC   light teal — banner background
```

### Dark mode (via OS `prefers-color-scheme`)

```
  bg          #1B130C   warm dark wood
  bg-soft     #221912   deeper
  surface     #28201A   lifted dark — phone interior · cards
  ink         #F2E5C7   warm cream — body text
  muted       #A09076   warm dim
  rule        #3D3122   dark hairline
  rule-soft   #322819

  warm        #DA8943   amber lifts (more saturation, less darkness)
  cool        #6FA086   forest lifts (lighter, more cyan)
  success     #A0BC58
  error       #D26B5C
  gold        #D4AC4A
```

### Color discipline

- **`warm` (amber)** is reserved for: brand wordmark accent (the `.` after BeerBuddy), BEST DEAL eyebrow text, primary CTAs, the "now" marker on the price-trend graph, and the focused border of the BEST DEAL card. Do not use elsewhere.
- **`cool` (forest)** is reserved for: text links, the active filter chip background, the price-trend line, and the active sort-dropdown border.
- **`success`** is reserved for the savings amount on a deal (`▼ 22% off`). Not used as a generic positive color; this is a single-purpose accent.
- **`error`** is reserved for hard errors (failed admin auth, quarantine entries, network failures).
- **Do not introduce new colors without an entry in the Decisions Log.**

### Contrast (WCAG 2.1 AA)

All ink on bg / surface combinations exceed 4.5:1. Muted on bg meets 4.5:1 for small text. Verify any new color combination with a contrast checker before adoption.

## Spacing

- **Base unit:** 4px
- **Density:** Comfortable. Not compact (data-table feel) and not airy (luxury feel) — the brewery between rushes.
- **Scale:**

```
  2xs   2px      half-step adjustments
  xs    4px      icon-to-label gap
  sm    8px      tight grouping
  md    16px    default spacing
  lg    24px    section padding
  xl    32px    page padding
  2xl   48px    section breaks
  3xl   64px    hero / page header
```

## Layout

- **Approach:** Grid-disciplined, single-column. The structural restraint is deliberate.
- **Mobile primary:** 320–480px portrait. Optimized layout.
- **Tablet / desktop ≥768px:** Same single-column layout, centered, max-width 480px (per `/plan-design-review` Issue 7A — "mobile-on-desktop" interpretation of "secondary web").
- **Border-radius scale:**

```
  sm    4px       chips, inputs, buttons, small cards
  md    6px       larger cards, modals
  lg    10px     primary content blocks (rare)
  full  9999px   reserved (currently no full-pill components in v0.4)
```

The choice of small radii (4–6px) is intentional — large rounded corners read as "playful SaaS." Small radii read as "considered editorial."

- **Borders:** 1px hairlines for dividers and most card boundaries. 1.5px reserved for emphasis (banner borders, swatch borders). 2px reserved for the BEST DEAL card's left-edge accent.
- **Two-tone composition:** When designing any new screen, decide first whether it sits on the **page (wheat-oak)** or on the **content surface (white)**. Cards, inputs, modals, app-content interiors → white. Page chrome, between-card whitespace, hero areas → wheat-oak.

## Motion

- **Approach:** Intentional, settling — never bouncy. Express character through ease curves, not spring physics.
- **Easing:** `cubic-bezier(0.16, 1, 0.3, 1)` for entrances and most transitions ("settle" — a fast start that decelerates gracefully). `ease-in-out` for symmetric transitions.
- **Durations:**

```
  micro   100ms    hover state changes (background, border-color)
  short   240ms    layout shifts, dropdowns, banner dismiss
  medium  400ms    theme transition, page entrance, mode toggle
```

- **No `transform: translateY(-1px)` lift on hover.** The v0.3 iteration tried this; it read as "playful SaaS." Removed in v0.4.
- **`prefers-reduced-motion`:** Disable ALL transitions and animations. Respected globally with:

```css
@media (prefers-reduced-motion: reduce) {
  * { transition: none !important; animation: none !important; }
}
```

## Component vocabulary

The system intentionally has a small component vocabulary — most surfaces are built from typography + rules + spacing rather than from named components.

| Component | Treatment |
|-----------|-----------|
| **Button (primary)** | Ink-filled (`#1F1610` light / `#F2E5C7` dark), 1px ink border, 14px Bricolage 500, 4px radius, 44px min-height. No drop shadow, no transform on hover. |
| **Button (ghost)** | Transparent, 1px ink border, ink text, 4px radius. Hover: bg-soft. |
| **Filter chip** | Transparent or ink-filled (active), 1px rule border, 13px Bricolage 500, 4px radius (square-ish, not pill), 32px min-height. |
| **Sort dropdown** | Same shape as ghost button with `▾` indicator. |
| **Input** | 1.5px rule border, 16px Bricolage 500, 4px radius, 48px min-height. Focus: 2px cool outline + 2px offset, border becomes cool. |
| **BEST DEAL eyebrow** | Pure typography: 10px Geist Mono small-caps, amber color, 0.18em letter-spacing. NO chrome (no border, no fill, no pill). |
| **Deal card** | Chrome-less. Hairline `1px solid rule` bottom-border separates rows. The BEST DEAL card gets a 2px amber `border-left` and 14px left padding — that single accent does the visual work. |
| **Store row** | Same chrome-less treatment as deal cards. Right side stacks: `$X.XX` price, then "Directions →" as an underlined cool-color text link below. Not a button. |
| **Banner (limited history)** | 1.5px cool border, cool-soft background, ink text, ⓘ icon in cool, 6px radius. |
| **Toast (success/error)** | 1.5px rule border, surface (white) background, success/error glyph prefix, 6px radius. |
| **Badge** (e.g., "BEST DEAL · 22% OFF") | See "BEST DEAL eyebrow" above — typography only, no chrome. |

### What the system explicitly does NOT include

- Filled gradient buttons
- Drop shadows on cards (the box-shadow on the phone-mockup frame in the preview is a one-off device chrome, not a card-level pattern)
- Pill-shaped filter chips (intentionally square)
- Star icons or marketing-sticker treatments on best-deal markers
- Solid-fill icon buttons (the directions link is text-only)
- Italic prices (looks precious; rejected in v0.4)
- Decorative ornaments (`※`, fleurons, etc. — rejected in v0.4)

## Microcopy & Voice

- **Voice:** Friendly, mature, direct. Verbs like "show," "skip," "save," "verify." Not "discover," "explore," "unlock."
- **Examples:**
  - Entry tagline: "Best beer deals in Nevada County."
  - Entry prompt: "What's nearby?"
  - Entry help: "Enter your ZIP and we'll do the rest."
  - Limited-history banner: "Building the price database. Most calls limited until July."
  - Slow-week empty state: "Quiet week. No standout deals — check back Friday."
  - Disclaimer: "Prices may vary at point of purchase. Verify before driving."

## Product Principle: Zero User Labor

**The user never works to make BeerBuddy better.** Every piece of data the app needs is sourced from the web by the developer — chain websites, weekly ads, delivery aggregators (DoorDash / Caviar / Instacart / Toast). The user's only job is to open the app and read what's there.

This principle is **non-negotiable in v1** and shapes every UI and microcopy decision:

### What this means for the UI

- **No "submit a price" / "report an error" / "improve this page" CTAs anywhere in the app.** Not in the footer, not on detail pages, not in empty states.
- **No surveys, no feedback prompts, no "how are we doing?" toasts.** If feedback is needed, the developer asks specific friends in person — not the broad user base.
- **No required signups for core utility.** The app works on a fresh load with just a ZIP. Email/SMS subscriptions (the future "Beer Drop" feed in design doc Open Q #7) are opt-in for delivery, not contribution — and live in a single restrained section, never as a popup or modal.
- **No upload affordances in the public app.** The admin price-entry form (for indie stores with zero web presence) exists at `/admin/indie` and is gated by a developer password. It is never linked from public pages, never mentioned in microcopy.
- **No "you can help by..." nudges.** No gamification, no badges, no contributor leaderboards.
- **Empty states explain reality, not invite contribution.** "Quiet week — check back Friday" — not "Help us find more deals!"
- **Limited-history caveat sets expectations, doesn't request help.** "Building the price database — most calls limited until July" — not "Tell us about prices to help us improve."

### What this means for the developer

The developer (you) does the work users would otherwise be asked to do — and that work is now mostly automatic via web scraping and delivery aggregators, not in-store audits or manual entry. The narrow case where it isn't automatic (a zero-web-presence indie) is admin-form work the developer does behind a password.

### Why this matters

The app is positioned as a service that works *for* the user, not a community tool the user contributes to. This is the difference between "BeerBuddy saved me $4 again" and "I should remember to update BeerBuddy this week." Apps in the second category get abandoned. The ones in the first get reopened on Friday afternoons forever.

If a future feature appears to require user labor to function, that feature is either (a) re-architected to source the data from the web, or (b) cut from scope. There is no third option.

## Accessibility (WCAG 2.1 AA — locked)

- All interactive elements have ≥44×44 touch targets (chips currently 32px tall — needs widening on launch).
- Focus rings: 2px cool outline + 2px offset, applied to inputs and any focused interactive.
- All images: alt text. The price-trend SVG has `<title>` and `<desc>` describing min/max/current.
- All icons used semantically (← arrow, ▾ dropdown, ⓘ banner) get `aria-label` or are accompanied by visible text.
- Color contrast: body text ≥4.5:1, large text ≥3:1, UI chrome ≥3:1.
- `prefers-reduced-motion`: respected globally.
- `prefers-color-scheme`: dark mode supported automatically.
- Keyboard navigation: tab order matches visual order. ZIP input → submit → use-my-location on entry. Sort → filter chips → first card → next on deal list.
